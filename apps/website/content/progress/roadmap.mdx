## 已经走完的路

Playground 演示场分两个阶段推进，均已完成：

| 阶段 | 做了什么 | 结果 |
| --- | --- | --- |
| **Phase A** | 定义菜单树、脚本化录入菜单、四端先落占位页 | 骨架打通 |
| **Phase B** | 先做 React 基准（7 页演示内容），再依次跟进 Next → Vue → Nuxt | 四端全对齐 |

分两个阶段的关键在于：先把**菜单与路由骨架**在四端都立起来，再填内容。这样内容阶段只需要复制已经验证过的结构，不会出现"某一端做到一半发现路由结构不对，四端一起返工"。

## 下一步：Phase 0 演示上线准备

在正式对外演示之前，需要先把环境收拾干净。Phase 0 的目标是**让演示环境可以被陌生人安全地访问**：

| 事项 | 目的 |
| --- | --- |
| faker 数据重置 | 演示数据可重复生成，随时回到干净状态 |
| 只读守卫（`DEMO_READONLY`） | 访客可以浏览，但不能改数据 |
| 快捷登录 | 提供预置账号，省掉注册流程 |
| 日志降噪 | 演示流量不污染审计日志 |
| 契约升到 v1.10.0 | 承载上面这些演示期能力 |

## 之后：Phase C Dashboard 概览

| 内容 | 说明 |

## 两道路闸

Phase 0 与 Phase C 都排在 Gate 之后，Gate 的通过条件是：**Nuxt 端功能全对齐 + 通过冒烟测试**。

把 Gate 放在这两个阶段之前，是为了避免在演示环境还没稳定时就开始堆新功能 —— 否则新功能的问题和环境的噪音会混在一起，排查成本翻倍。

## 上线清单

五个应用**目前都还没有正式上线**。统一上线时需要执行的事项包含：

- NestJS 端配置**保活 ping**（免费实例会休眠，冷启动会拖垮演示第一印象）
- **CORS 白名单**从本地端口收敛到线上域名
- 各应用环境变量在目标平台配置完毕（密钥不进仓库）
- 数据库迁移在目标环境执行到位
- 各端构建产物验证通过

平台分工见[功能矩阵](/docs/progress/feature-matrix)页的部署状态表。
