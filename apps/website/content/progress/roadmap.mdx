## 部署现状

六个应用全部上线，域名生效，线上即演示环境（只读演示模式，登录页可快捷登录）：

| 应用 | 线上地址 | 平台 |
| --- | --- | --- |
| React | [react.baiwumm.com](https://react.baiwumm.com) | Vercel（静态 SPA） |
| Vue | [vue.baiwumm.com](https://vue.baiwumm.com) | Vercel（静态 SPA） |
| Next.js | [next.baiwumm.com](https://next.baiwumm.com) | Vercel |
| Nuxt | [nuxt.baiwumm.com](https://nuxt.baiwumm.com) | Vercel |
| NestJS | [nest.baiwumm.com](https://nest.baiwumm.com) | Render |
| website（本站） | [better-admin.baiwumm.com](https://better-admin.baiwumm.com) | 腾讯云 EdgeOne Makers（静态导出） |

- React / Vue 是纯静态 SPA，深链回退由各端 `vercel.json` 的 `rewrites: /(.*) → /index.html` 提供。
- Next / Nuxt 依赖 postgres.js 的 TCP 直连，必须运行在支持长连接的平台（Vercel），不能部署到 Workers 运行时。
- 演示模式开关只在 Nest / Next / Nuxt 三端配置 `DEMO_MODE=true`；React / Vue 通过 NestJS 继承该行为。

## 线上保活与防刷

| 层 | 覆盖 | 规则 |
| --- | --- | --- |
| Render 保活 | `GET /api/health`（无鉴权、不访问数据库） | UptimeRobot 以 HTTP(S) 类型每 5 分钟探活；不要用 PING 类型 |
| Vercel WAF | Next / Nuxt 的 `/api/auth/*` | Fixed Window 60 秒 / 20 次 per IP，超限 429 |
| NestJS throttler | React / Vue 的认证入口 | `login` / `demo-login` 20 次/60s，`refresh` 60 次/60s，超限统一 429 信封 |

Render 入口实际是 3 跳代理（CF for SaaS 边缘 + 私网代理），Nest 的 `trust proxy` 必须定值 3，限流计数才不会抖散。

## CI

六端矩阵覆盖 `lint` / `typecheck` / `test` / `build`，另有 Nest e2e 使用 CI 内的自托管 Postgres 容器（不连 Supabase）。线上 API 一致性由 `contract-diff` 脚本按契约逐项比对。

部署顺序、环境变量与回滚步骤见仓库 `docs/launch-runbook.md`。
