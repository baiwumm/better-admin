## 已经走完的路

Playground 演示场分两个阶段推进，之后的 Phase 0 / Phase C 也都已收口：

| 阶段 | 做了什么 | 结果 | 时间 |
| --- | --- | --- | --- |
| **Phase A** | 定义菜单树、脚本化录入菜单、四端先落占位页 | 骨架打通 | 09-14 |
| **Phase B** | 先做 React 基准，再依次跟进 Next → Vue → Nuxt | 四端全对齐（现为 10 页） | 09-16 |
| **Phase 0** | 演示环境加固：只读守卫、快捷登录、数据重置、日志降噪 | 陌生人可安全访问 | 09-18 |
| **Phase C** | Dashboard 概览：KPI + 登录趋势 + 角色占比 + 最新动态，四端对齐 | 功能矩阵补齐最后一块 | 09-19 |

分阶段的关键在于：先把**菜单与路由骨架**在四端都立起来，再填内容。这样内容阶段只需要复制已经验证过的结构，不会出现"某一端做到一半发现路由结构不对，四端一起返工"。

中间那道 **Gate** 的通过条件是「Nuxt 端功能全对齐 + 通过冒烟测试」，已于 09-16 通过——把闸口放在演示环境稳定之前，是为了避免新功能的问题和环境噪音混在一起。

## 上线收官（2026-09-23）

六个应用功能全部就绪后统一上线，全部域名已生效，线上即演示环境：

| 事项 | 落地结果 |
| --- | --- |
| NestJS 外部保活 | `GET /health` 已实现（契约相对路径，实际带全局前缀为 `/api/health`）；UptimeRobot 以 **HTTP(S) 类型**每 5 分钟探活——⚠️ 上线当日曾误配为 PING（ICMP）类型，它对 Render 入口永远 Down、保活实际未生效 6 小时，已改判并复验（`uptimeSeconds` 跨采样连续）；冷启动自此消除 |
| CORS 白名单收敛 | 已收敛为线上域名；Nest 只服务 React / Vue 两端，Next / Nuxt 是独立全栈不走它 |
| SPA 直链回退 | React / Vue 由 `wrangler.jsonc` 的 `not_found_handling=single-page-application` 提供 |
| 演示模式开关 | 三端（Nest / Next / Nuxt）线上配 `DEMO_MODE=true`，只读守卫 + 快捷登录生效 |
| 环境变量与迁移 | 各平台变量配齐（密钥不进仓库）；迁移真源在 Nest 端，线上库一次到位 |
| 构建验证 | CI 已挂接六端 17 步矩阵（lint / typecheck / test / build）；上线当日线上 contract-diff 31 步一致 |

平台分工：React / Vue → Cloudflare Workers（Static Assets，SPA 深链回退由 `not_found_handling` 负责），Next / Nuxt → Vercel（postgres.js TCP 直连不支持 Workers 运行时），本站 → Cloudflare Workers（静态导出），NestJS → Render。部署与冒烟全记录见仓库 [`docs/launch-runbook.md`](https://github.com/baiwumm/better-admin/blob/main/docs/launch-runbook.md)。
