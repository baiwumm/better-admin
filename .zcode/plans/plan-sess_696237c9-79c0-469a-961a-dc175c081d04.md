## Nest e2e 测试基建实施方案

### 目标与范围

给 `apps/nest`（当前 0 测试）从零补 e2e 测试：起真实 Nest 应用 + 真实 PostgreSQL，走 HTTP 断言**行为语义**（权限拦截、super_admin 保护、演示守卫、密码策略、令牌轮换）——补 contract-diff（31 步只读 GET 形状对比）覆盖不到的写路径与安全边界。只动 `apps/nest` 与仓库级 CI/文档，不碰四个前端。

### 技术选型（已拍板）

- **框架 vitest**（`^4.1.11`，与全仓四端同大版本）；**@nestjs/testing 11.2.1**（与现有 @nestjs/* 同版本精确锁）。不加 supertest——`app.listen(0)` 随机端口 + Node 原生 fetch + 轻量 `api()` 请求助手，断言写法与既有 curl/contract-diff 场景直译。
- **隔离：Supabase 同库 `e2e` schema**。测试连接串带 `options=-c search_path=e2e`，`process.env.DATABASE_URL` 在 import AppModule 前被替换为该串——应用内 `db/client.ts` 零侵入自动连进 e2e schema。pgbouncer 6543 不支持 startup parameters，故要求 5432 直连串。
- `.env.example` 补 `DATABASE_TEST_URL`（示例 + 注释）；`.env`（gitignore）由用户填真实 5432 直连串；缺失时测试启动报清晰错误，不静默回退到生产连接串。

### 测试库生命周期（global-setup.ts）

1. 校验 `DATABASE_TEST_URL` → 追加 search_path options；
2. `DROP SCHEMA IF EXISTS e2e CASCADE; CREATE SCHEMA e2e`（每次全新，天然幂等）；
3. 子进程跑 `pnpm db:migrate` → `pnpm db:seed`（与手工流程完全一致，seed 幂等已验证；`SEED_ADMIN_PASSWORD` 用默认 `admin123`，登录用例直接用）；
4. 跑完全部用例 teardown 再 DROP schema（`E2E_KEEP_SCHEMA=1` 时保留供调试）。

```
apps/nest/

  package.json            # + "test": "vitest run"
  test/
    setup/global-setup.ts # 上述 schema 生命周期
    setup/env.ts          # 测试 env 注入（JWT_SECRET 测试值、DEMO_MODE 等）
    setup/test-app.ts     # Test.createTestingModule(AppModule) → init → listen(0)；api() fetch 助手（自动 {data} 包络与 Authorization）
    setup/fixtures.ts     # drizzle 直插测试造数（受限角色/用户，username 前缀 e2e_）
    health.e2e-spec.ts    # /health 200；未带 token 打受保护端点 401；{data} 包络与 {code,message} 错误结构
    auth.e2e-spec.ts      # login 成功/错密 401；refresh 轮换 + 旧令牌重放 401；logout 后 refresh 失效；重置密码 bump tokenVersion 后旧 accessToken 401
    rbac.e2e-spec.ts      # super_admin /auth/me 返回归一全量位；超管免检；受限角色有位 200/无位 403；角色停用后权限即时回收
    super-admin.e2e-spec.ts # PUT /roles/{super_admin}/menus 403、DELETE 403、停用 403（SUPER_ADMIN_ROLE_PROTECTED）；仅剩一个活跃超管时摘绑 403、存在第二个超管时摘绑成功（SUPER_ADMIN_LAST_PROTECTED）
    demo.e2e-spec.ts      # DEMO_MODE=true 下未登录写请求 403 DEMO_READONLY（先于 401）；demo-login 两级随机 + 超管永不进池；白名单 6 端点放行；DEMO_MODE=false 时 demo-login 404（第二个 app 实例）
    password.e2e-spec.ts  # 弱密码/含空白 400；含用户名 PASSWORD_CONTAINS_USERNAME；同旧密 PASSWORD_SAME_AS_OLD；合法改密成功 + 旧 token 失效
```

### CI 挂接

`ci.yml` 新增独立 job `nest-e2e`（不动现有 17 步矩阵模板）：`services: postgres:16-alpine`（pg_isready 就绪检查），`DATABASE_TEST_URL=postgresql://postgres:postgres@localhost:5432/postgres`，步骤复用现有模板（pnpm 11 → Node 22 + pnpm 缓存 → frozen install → `pnpm test`）。同步更新矩阵里 nest 的「无 test 脚本，见台账 #46」注释。

### 实施验证点（动手时先确认）

- seed.ts 是否可直接 import（否则维持子进程执行）；drizzle migrator 在 search_path schema 下 migrations 表落位；
- `@nestjs/schedule` 的 cron 会注册但测试窗口内不触发，无副作用；LoggingInterceptor 写的 api 日志落在 e2e schema 内；
- 新 devDependency 均选发布超 24h 的版本，不触发 `minimumReleaseAge`（vitest 4.1.11 四端已在用；@nestjs/testing 11.2.1 与现依赖同批发布）。
